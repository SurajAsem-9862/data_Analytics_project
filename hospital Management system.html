Audit standard applied to every table

Each table below ends with the same four audit columns, shown highlighted: CreatedBy, CreatedDate, ModifiedBy, ModifiedDate. CreatedBy and ModifiedBy are INT foreign keys to User(UserID) — not free-text names — so every change is traceable to a real system account.

CreatedBy/CreatedDate are set once on INSERT and never change. ModifiedBy/ModifiedDate stay NULL until the first UPDATE, then are refreshed on every subsequent UPDATE (via application logic or an AFTER UPDATE trigger). This is why the User table is created first, as the foundation every other table's audit columns depend on.

UCreate User Table

Table: User

Store system login accounts for hospital staff (admins, doctors, receptionists, billing staff, etc.). Every CreatedBy/ModifiedBy audit column across the schema references UserID here, so this table must exist before the others.

FieldData TypeConstraint
UserIDINTPKIDENTITY(1,1), NOT NULL
UsernameVARCHAR(50)UQNOT NULL, UNIQUE
PasswordHashVARCHAR(256)NOT NULL — store a salted hash, never plain text
FullNameVARCHAR(150)NOT NULL
RoleVARCHAR(50)NOT NULL — e.g. Admin, Doctor, Receptionist, Billing, Nurse
DoctorIDINTFKNULL → Doctor.DoctorID (set only when Role = 'Doctor')
EmailVARCHAR(150)UQNULL, UNIQUE when provided
MobileNoVARCHAR(20)NULL
IsActiveBITDEFAULT 1
LastLoginDateDATETIMENULL
CreatedByINTAUDITFKNULL → User.UserID (self-reference; nullable for the first/seed account)
CreatedDateDATETIMEAUDITDEFAULT GETDATE()
ModifiedByINTAUDITFKNULL → User.UserID (self-reference)
ModifiedDateDATETIMEAUDITNULL
Relationships
  • DoctorID → Doctor(DoctorID) — optional, links a login account to its doctor profile
  • CreatedBy / ModifiedBy → User(UserID) — self-referencing
Constraint
  • Because Doctor is created after User but User.DoctorID references it, add this foreign key with an ALTER TABLE once Doctor exists (or defer FK creation until both tables are in place).
